## Resumen Ejecutivo

FighterIA v2 extiende la plataforma existente con tres módulos independientes que no rompen ninguna funcionalidad v1:

| Módulo | Propósito | Tablas nuevas | Endpoints nuevos |
|--------|-----------|--------------|-----------------|
| CRM | Gestión de gimnasios, trainers y leads comerciales | 3 (Gym, Trainer, Lead) | 11 |
| Blockchain | Certificación SHA-256 verificable de análisis completados | 1 (Certificate) | 2 |
| NLP | Feedback textual enriquecido generado localmente sin API externa | 0 (servicio puro) | 1 |

La integración con v1 es mínima: solo se modifica `backend/app/main.py` para registrar los tres routers nuevos, y `backend/app/models/__init__.py` para que SQLAlchemy registre los nuevos modelos antes del `create_all()`.

## Módulo 1: CRM

### Propósito

Gestiona el ciclo de vida comercial de la plataforma: los gimnasios que contratan FighterIA (Gym), los trainers asignados a cada gimnasio (Trainer), y los leads o prospectos en proceso de captación (Lead). Permite al equipo de ventas rastrear el funnel completo y consultar métricas agregadas por gimnasio.

---

### 1.1 Modelo de Datos — `backend/app/models/crm.py`

```python
"""
Module: models.crm
Description: CRM models — Gym (tenant), Trainer (staff) and Lead (sales pipeline)
"""
from sqlalchemy import Column, Integer, String, DateTime, ForeignKey, Text
from sqlalchemy.orm import relationship
from sqlalchemy.sql import func
from app.database import Base


class Gym(Base):
    __tablename__ = "gyms"

    id         = Column(Integer, primary_key=True, index=True)
    name       = Column(String(150), nullable=False)
    city       = Column(String(100), nullable=True)
    country    = Column(String(100), nullable=True)
    plan       = Column(String(30), nullable=False, default="free")
    # plan values: "free" | "pro" | "enterprise"
    created_at = Column(DateTime(timezone=True), server_default=func.now(), nullable=False)

    trainers   = relationship("Trainer", back_populates="gym", lazy="select")
    leads      = relationship("Lead",    back_populates="gym", lazy="select")


class Trainer(Base):
    __tablename__ = "trainers"

    id      = Column(Integer, primary_key=True, index=True)
    gym_id  = Column(Integer, ForeignKey("gyms.id"), nullable=False, index=True)
    user_id = Column(Integer, ForeignKey("users.id"), nullable=False, index=True)
    role    = Column(String(50), nullable=False, default="coach")
    # role values: "coach" | "head_coach" | "admin"
    status  = Column(String(20), nullable=False, default="active")
    # status values: "active" | "inactive" | "pending"

    gym  = relationship("Gym",  back_populates="trainers")
    user = relationship("User", lazy="select")


class Lead(Base):
    __tablename__ = "leads"

    id         = Column(Integer, primary_key=True, index=True)
    gym_id     = Column(Integer, ForeignKey("gyms.id"), nullable=True, index=True)
    name       = Column(String(100), nullable=False)
    email      = Column(String(255), nullable=False, index=True)
    phone      = Column(String(30), nullable=True)
    status     = Column(String(30), nullable=False, default="new")
    # status values: "new" | "contacted" | "qualified" | "converted" | "lost"
    source     = Column(String(50), nullable=True)
    # source values: "organic" | "referral" | "paid_ad" | "event" | "direct"
    notes      = Column(Text, nullable=True)
    created_at = Column(DateTime(timezone=True), server_default=func.now(), nullable=False)

    gym = relationship("Gym", back_populates="leads")
```

## Módulo 2: Blockchain

### Propósito

Genera un certificado de autenticidad SHA-256 por cada análisis completado. El hash es determinístico: dado el mismo `analysis_id`, `user_id`, `score` y `timestamp`, siempre produce el mismo resultado. Cualquier persona puede verificar un certificado por hash sin necesidad de autenticación, lo que lo hace apto para compartir públicamente o incluir en curriculums deportivos.

---

### 2.1 Modelo de Datos — `backend/app/models/blockchain.py`

```python
"""
Module: models.blockchain
Description: Certificate model — SHA-256 proof of completed analysis
"""
from sqlalchemy import Column, Integer, String, DateTime, ForeignKey
from sqlalchemy.orm import relationship
from sqlalchemy.sql import func
from app.database import Base


class Certificate(Base):
    __tablename__ = "certificates"

    id              = Column(Integer, primary_key=True, index=True)
    analysis_id     = Column(Integer, ForeignKey("analyses.id"),
                             nullable=False, unique=True, index=True)
    hash            = Column(String(64), nullable=False, unique=True, index=True)
    # 64 hex chars = SHA-256 output
    issued_at       = Column(DateTime(timezone=True),
                             server_default=func.now(), nullable=False)
    verified_count  = Column(Integer, default=0, nullable=False)

    analysis = relationship("Analysis", lazy="select")
```

**Campos detallados:**

| Campo | Tipo SQL | Constraints | Descripción |
|-------|----------|-------------|-------------|
| id | INTEGER | PK, AUTOINCREMENT | ID único |
| analysis_id | INTEGER | FK → analyses.id, UNIQUE, INDEX | Un análisis genera exactamente un certificado |
| hash | VARCHAR(64) | UNIQUE, NOT NULL, INDEX | SHA-256 hex digest de 64 caracteres |
| issued_at | DATETIME | DEFAULT NOW | Momento de emisión del certificado |
| verified_count | INTEGER | DEFAULT 0, NOT NULL | Contador de verificaciones públicas |

**Constraint clave:** `analysis_id` es UNIQUE — no puede haber dos certificados para el mismo análisis. El endpoint de generación devuelve el certificado existente si ya fue emitido (operación idempotente).

### 2.2 Servicio — `backend/app/services/blockchain_service.py`

```python
"""
Module: services.blockchain_service
Description: SHA-256 certificate generation and public verification.
             No external API dependencies — pure stdlib hashlib.
"""
import hashlib
from sqlalchemy.orm import Session
from app.models.blockchain import Certificate
from app.models.analysis import Analysis


def _build_payload(analysis: Analysis) -> str:
    """
    Construct the canonical string to hash.
    Format: "{analysis_id}:{user_id}:{global_score:.4f}:{completed_at_iso}"
    completed_at is used (not created_at) because it is set only when
    status='completed', making the hash stable once the analysis is done.
    """
    score = analysis.global_score if analysis.global_score is not None else 0.0
    ts    = analysis.completed_at.isoformat() if analysis.completed_at else ""
    return f"{analysis.id}:{analysis.user_id}:{score:.4f}:{ts}"


def generate_certificate(db: Session, analysis_id: int) -> Certificate:
    """
    Generate (or retrieve existing) SHA-256 certificate for a completed analysis.
    Raises ValueError if analysis not found or not completed.
    """
    analysis = db.query(Analysis).filter(Analysis.id == analysis_id).first()
    if not analysis:
        raise ValueError("Análisis no encontrado.")
    if analysis.status != "completed":
        raise ValueError("Solo se pueden certificar análisis con status 'completed'.")

    # Idempotent: return existing certificate if already generated
    existing = db.query(Certificate).filter(
        Certificate.analysis_id == analysis_id
    ).first()
    if existing:
        return existing

    payload = _build_payload(analysis)
    digest  = hashlib.sha256(payload.encode("utf-8")).hexdigest()

    cert = Certificate(analysis_id=analysis_id, hash=digest)
    db.add(cert)
    db.commit()
    db.refresh(cert)
    return cert


def verify_certificate(db: Session, hash_value: str) -> dict:
    """
    Public verification: find certificate by hash, increment verified_count,
    and return certificate data + recomputed hash match status.
    """
    cert = db.query(Certificate).filter(Certificate.hash == hash_value).first()
    if not cert:
        return {"valid": False, "certificate": None}

    # Recompute hash to confirm integrity
    payload   = _build_payload(cert.analysis)
    recomputed = hashlib.sha256(payload.encode("utf-8")).hexdigest()
    is_valid  = recomputed == hash_value

    if is_valid:
        cert.verified_count += 1
        db.commit()

    return {"valid": is_valid, "certificate": cert}
```

**Algoritmo de generación del hash:**

```
payload  = f"{analysis.id}:{analysis.user_id}:{analysis.global_score:.4f}:{analysis.completed_at.isoformat()}"
hash     = SHA-256(payload.encode("utf-8")).hexdigest()
```

Ejemplo concreto:
```
analysis_id  = 42
user_id      = 7
global_score = 83.25 → "83.2500"
completed_at = "2026-06-05T14:32:00+00:00"

payload  = "42:7:83.2500:2026-06-05T14:32:00+00:00"
hash     = SHA-256("42:7:83.2500:2026-06-05T14:32:00+00:00")
         = "a3f1e9..." (64 hex chars)
```

## Módulo 3: NLP

### Propósito

Genera un párrafo de feedback textual personalizado y enriquecido basado exclusivamente en los scores numéricos de un análisis. No depende de APIs externas (sin OpenAI, sin Hugging Face). La lógica es puramente local: rangos de score → selección de plantillas → composición dinámica.

Este módulo complementa al `feedback_service.py` existente, que genera correcciones por articulación. El NLP service genera un resumen holístico de rendimiento orientado al atleta.

---

```python
    "Para mejorar, debes enfocarte en {weaknesses}, que {verb} por debajo del nivel esperado.",

    "Tu técnica muestra una distribución muy pareja entre todas las dimensiones.",
]

_NO_STRENGTH = [
    "Esta sesión refleja margen de mejora en todas las dimensiones evaluadas.",
    "El análisis indica que todas las áreas necesitan trabajo para alcanzar el nivel objetivo.",
]


# ── Main function ──────────────────────────────────────────────────────────

def generate_nlp_feedback(scores: Dict[str, float]) -> str:
    """
    Compose a personalized feedback paragraph from score dict.
    Keys expected: potencia, equilibrio, alineacion, velocidad (0-100 each).
    Missing keys default to 0.
    """
    dimensions = ["potencia", "equilibrio", "alineacion", "velocidad"]
    classified = {
        dim: _classify(scores.get(dim, 0.0))
        for dim in dimensions
    }

    # Separate strengths (avanzado+) from weaknesses (básico-)
    strong_dims   = [d for d in dimensions if classified[d] in ("avanzado", "sobresaliente")]
    weak_dims     = [d for d in dimensions if classified[d] in ("básico", "deficiente")]
    middle_dims   = [d for d in dimensions if d not in strong_dims and d not in weak_dims]

    sentences = []

    # 1. Opening: level descriptions for each dimension
    for dim in dimensions:
        sentences.append(_LEVEL_DESC[dim][classified[dim]])

    # 2. Strengths sentence
    if strong_dims:
        names = " y ".join(_DIM_NAMES[d] for d in strong_dims)
        intro = _STRENGTH_INTROS[len(strong_dims) % len(_STRENGTH_INTROS)]
        sentences.append(intro.format(strengths=names))
    else:
        sentences.append(_NO_STRENGTH[0])

    # 3. Weaknesses sentence
    if weak_dims:
        names = " y ".join(_DIM_NAMES[d] for d in weak_dims)
        verb  = "requieren" if len(weak_dims) > 1 else "requiere"
        intro = _WEAKNESS_INTROS[len(weak_dims) % len(_WEAKNESS_INTROS)]
        sentences.append(intro.format(weaknesses=names, verb=verb))
    else:
        sentences.append(_NO_WEAKNESS[0])

    # 4. Recommendations: weaknesses first, then middle, then strong (brief)
    priority_order = weak_dims + middle_dims + strong_dims
    for dim in priority_order[:3]:  # cap at 3 recommendations for readability
        sentences.append(_RECOMMENDATIONS[dim][classified[dim]])

    return " ".join(sentences)
```

## Notas de Implementación

### 1. Compatibilidad con SQLite

Los tres módulos usan únicamente tipos SQLAlchemy compatibles con SQLite (`Integer`, `String`, `Float`, `Boolean`, `DateTime`, `Text`, `ForeignKey`). No se usa JSON nativo ni arrays, respetando el patrón del proyecto v1.

### 2. Creación de tablas

Al añadir los nuevos modelos en `models/__init__.py` antes de que `main.py` llame a `Base.metadata.create_all(bind=engine)`, las 4 tablas nuevas (`gyms`, `trainers`, `leads`, `certificates`) se crean automáticamente en el mismo SQLite sin migraciones manuales. Esto es consistente con el comportamiento actual del proyecto.

### 3. Idempotencia del certificado

El endpoint `POST /certificates/generate/{analysis_id}` es idempotente por diseño. Si se llama dos veces para el mismo `analysis_id`, la segunda llamada recupera el certificado existente en lugar de lanzar un error. Esto simplifica el cliente frontend que puede llamar al endpoint sin verificar previamente si ya existe.

### 4. Seguridad del hash SHA-256

El hash es computacionalmente seguro para verificación de integridad, pero NO es una firma criptográfica (no hay clave privada). Si se requiriera no-repudiabilidad criptográfica en el futuro, se debería añadir HMAC-SHA256 con una clave secreta almacenada en `settings`. Para el MVP, SHA-256 determinístico es suficiente.

### 5. NLP sin estado

`nlp_service.generate_nlp_feedback()` es una función pura sin efectos secundarios. El router NLP no accede a la base de datos. Si en el futuro se desea persistir el feedback NLP, bastará añadir el campo `nlp_feedback TEXT NULLABLE` a la tabla `analyses` y llamar al servicio desde `analysis_service.run_analysis()`.

### 6. Autorización en CRM

Los endpoints CRM requieren autenticación JWT pero actualmente no implementan control granular de roles (cualquier usuario autenticado puede acceder). Para producción se recomienda añadir una verificación de `account_type == "instructor"` o un campo `is_admin` en el modelo `User` antes de exponer los endpoints CRM a usuarios generales.

### 7. Paginación en CRM

Los endpoints `GET /crm/gyms` y `GET /crm/trainers` y `GET /crm/leads` deben implementar paginación con `?page=1&limit=20` siguiendo el mismo patrón que `GET /analysis/me` en v1 (`AnalysisListResponse`).

### 8. Índices de base de datos

Índices adicionales recomendados para rendimiento en producción:
- `idx_leads_status` en `leads.status` (filtrado frecuente por funnel)
- `idx_leads_email` en `leads.email` (búsqueda por email ya definida con `index=True`)
- `idx_certificates_hash` en `certificates.hash` (ya definida con `index=True` — verificación pública)
- `idx_trainers_gym_id` en `trainers.gym_id` (ya definida con `index=True`)
